NVCF — NVIDIA Cloud Functions

Serverless GPU inference  ·  Top of stack  ·  User-facing AI platform

The consumption layer of DSX OS. Exposes models as serverless functions and endpoints — OpenAI-compatible APIs, streaming, gRPC/HTTP. Owns endpoint lifecycle, routing policy, rate limits, identity/auth, multi-tenancy, metering, and scale-to-zero. Developers ship a model; NVCF handles the GPUs beneath.

Scale-to-zero autoscaling Function & endpoint lifecycle OpenAI-compatible APIs Multi-tenant isolation & metering Global multi-region routing
DSX OS benefit: Turns the GPU cluster into a self-service, pay-per-use inference cloud. Teams consume LLM / multimodal / classic-ML inference through a stable API without touching nodes, operators, or schedulers — maximizing utilization and shrinking time-to-first-token for the business.

Grove — Multi-Node Inference Orchestration

Kubernetes API for gang-scheduled, topology-aware inference systems

A single declarative Kubernetes API for orchestrating any AI inference workload — from a single pod to systems sharded across tens of thousands of GPUs. Grove models a disaggregated serving deployment (prefill, decode, router, leader/workers) as one coherent, hierarchically-scaled unit.

PodCliqueGroup of pods sharing a role (e.g. prefill, decode, frontend), each independently configured.
PodCliqueScalingGroupBundles cliques that must scale & schedule together as one gang.
PodCliqueSet / PodGangTop-level replica + scheduler API guaranteeing minimum-replica gang scheduling.
Topology-aware placementCo-locates tightly-coupled components inside NVLink / rail domains.
Hierarchical gang schedulingAll-or-nothing startup prevents partial deploys & GPU deadlock.
Startup ordering & multi-level autoscaleEnforces leader→worker sequencing; scales roles independently within gang limits.
DSX OS benefit: Makes disaggregated, multi-node inference deployable and reliable. Gang scheduling eliminates wasted GPUs from half-scheduled deployments; topology awareness keeps prefill↔decode KV transfers on the fastest interconnects — directly boosting throughput per dollar.

NVIDIA Dynamo — Distributed Inference Engine

Datacenter-scale serving runtime  ·  three pluggable backends

The inference brain of the stack. Dynamo is a backend-agnostic, distributed serving framework that runs the same disaggregated architecture across all three leading engines:

TensorRT-LLM vLLM SGLang
PD DisaggregationSplits Prefill and Decode onto separate, independently-scaled GPU pools — each phase runs on hardware tuned to its compute vs. memory profile.
Cache-Aware RoutingKV-aware smart router sends requests to the worker that already holds the matching KV cache — up to ~2× faster time-to-first-token, less recompute.
KV Block Manager (KVBM)Tiers KV cache across GPU → CPU → SSD → remote, extending effective context beyond GPU memory limits.
SLA-driven PlannerProfiles load and right-sizes prefill/decode pools to hit latency targets at lowest TCO.
NIXL transfer libraryLow-latency GPU-to-GPU data / KV movement; ~7× faster replica & model startup.
Backend-agnostic APIOne control plane, one deployment model — swap engines without re-architecting the service.
DSX OS benefit: Decouples the two phases of LLM inference so each scales on its own economics, and reuses KV cache instead of recomputing it. The result is dramatically higher tokens/sec/GPU and lower latency — the core efficiency win of the whole factory.

GPU Operator + Network Operator

Kubernetes-native hardware enablement for GPUs & high-speed fabric

Two Kubernetes operators that make accelerated hardware a first-class, self-managing resource on the cluster provisioned below.

GPU OperatorAutomates the full NVIDIA software lifecycle: drivers, container toolkit, device plugin, DCGM monitoring, MIG partitioning, and node feature discovery.
Network OperatorDeploys the accelerated networking stack: Mellanox OFED/DOCA drivers, RDMA/RoCE, GPUDirect, SR-IOV, and secondary networks for east-west traffic.
MIG multi-instance GPU DCGM telemetry GPUDirect RDMA RoCE / InfiniBand SR-IOV & secondary nets
DSX OS benefit: Removes manual driver/fabric wrangling and guarantees every node exposes GPUs and RDMA networking consistently. GPUDirect + RoCE give Dynamo's disaggregated KV transfers the low-latency path they need — the fabric that makes multi-node inference fast.

BCM — Base Command Manager

Bare-metal provisioning & Kubernetes deployment  ·  Foundation of the stack

The bedrock IaaS layer (formerly Bright Cluster Manager). BCM provisions bare-metal GPU nodes from a golden image, then stands up and manages the Kubernetes cluster that everything above runs on — plus monitoring, health, and lifecycle for the whole fleet.

Bare-metal OS provisioning (PXE / image-based) Kubernetes deployment & management Cluster monitoring & health checks GPU & driver management Multi-tenant HPC + AI
DSX OS benefit: Provisions and continuously manages the physical AI factory — turning racks of GPU servers into a healthy, monitored, Kubernetes-ready cluster in hours instead of weeks. Everything above (operators, Dynamo, Grove, NVCF) inherits a consistent, observable foundation.
